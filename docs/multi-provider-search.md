# Multi-provider search

Feature-branch work, **not part of the frozen 0.2.7 release**. No live catalogue, saved lists, speakers or installation have been changed to test it.

## Behaviour

- Artist-first MA search and track-only demo search are unchanged. Participants may switch to tracks. MA's library and connected sources remain included; there is no Spotify/Tidal-specific search filter or second catalogue API.
- Matching MA provider-instance/item mappings or valid MusicBrainz artist IDs group artist rows. Releases require a MusicBrainz **release** ID or mapping; release-group IDs/barcodes alone are not enough. Tracks require a recording ID, ISRC or mapping, with exact normalized title/version/artist/context guards. Names alone never match. Case/Unicode normalization is not fuzzy matching; punctuation, edition words, album appearance, conflicting known years, duration, disc/track positions, explicit flags and conflicting IDs are preserved. Complete-link grouping prevents an ambiguous mapping bridge from merging contradictory identities.
- Source names come from public MA provider domains, not account names/instance IDs. A group lists all its exact choices; multiple entries for the same service receive stable option numbers. Alias titles remain available through their source. Missing identities mean separate, clearly sourced rows, even for a likely duplicate named Metallica. We do not invent a cross-provider match to make the screen look cleaner.
- Artist and album groups default to **All listed sources**. Browsing reads each known source and unions the results, so choosing a representative Spotify artist cannot hide Tidal-only albums. A source selector also permits browsing an individual catalogue, including sources beyond the automatic fanout limit.
- Track groups have **no default selection**. Choose an exact source to enable Add/Play. Its availability and metadata apply; an unavailable Spotify result does not switch to Tidal. Group references are rejected server-side for both capture and playback. Source variants retain participant/room/catalogue-bound encrypted references and the existing exact URI/provider/item/version recheck, durable saved descriptors, revocation and turn/reveal rules. Saved entries remain separate by exact recording identity; no list migration/deduplication or auto-play is performed.
- Library rows expand MA's explicit mappings to source choices. Mapping-only references use MA's documented `<provider>://<kind>/<item_id>` URI format and must pass the same strict exact-resolution guard. If a deployment rewrites instance identity/URI/version, the selection fails explicitly rather than weakening that guard or substituting another source. A legacy library-URI saved entry without an exact source must be reselected; it is retained, never rebound or deleted.

## Errors and resource bounds

MA global `music/search` can suppress individual provider failures and exposes no reliable per-source completion status in the supported response. Every MA search response/UI therefore explicitly marks coverage as unconfirmed, including empty results. An HTTP/auth/shape failure remains an error; it never falls back to demo or becomes an empty success. We do not claim that an empty search proves all catalogues are empty. Adding per-source health guarantees would require a verified upstream completion/error contract, not speculative requests.

For grouped browse, failed source requests are named in an incomplete-results notice, even if the successful sources return zero items. If every attempted source fails, the request fails and the previous choices remain available for retry. Upstream may itself suppress errors inside a provider listing; the app cannot reconstruct those omissions.

Search makes one MA request (`limit: 20`); at most 500 raw search items are accepted, grouped **before** any display reduction (the old early slice is removed). Each item accepts at most 100 explicit mappings/external IDs; at most 1,000 selectable variants are emitted per response. Artist/album browsing makes at most eight requests, two concurrently, with the existing eight-second per-request deadline and 2 MiB response cap. Each listing accepts 500 items and a union accepts 2,000 raw items; oversized results fail explicitly rather than silently dropping a provider. A fanout-cap notice directs users to source-specific browsing, and large album listings warn about possible upstream truncation. Exact references remain capped at 5,000; at most 1,000 browse groups retain at most 5,000 source-reference slots in total, not copies of upstream metadata. Expired/evicted sources require a fresh search. The existing twelve-hour expiry and credential/runtime revocation remain. No recursive source search, matching hydration, automatic retries, or playback writes are introduced.

Artist artwork is no longer cached by provider/name alone: that could attach one same-named artist's portrait to another. Only supplied item artwork and exact parent references are reused; missing portraits use the normal placeholder.

## Verification

Synthetic unit/integration and browser fixtures cover Spotify/Tidal identity grouping, same-name distinct artists, provider-only albums, release/recording distinctions, partial/full/empty source failure, fanout/concurrency bounds, source availability, opaque nested references, revocation, exact saved capture and rejection of substitutes. The full existing lifecycle/privacy/browser suite remains the regression gate. No real speaker validation or real-catalogue completeness claim follows from these fixtures.

Read-only upstream references reviewed: [MA media item models](https://github.com/music-assistant/models/blob/main/music_assistant_models/media_items/media_item.py), [external ID enums](https://github.com/music-assistant/models/blob/main/music_assistant_models/enums.py), [provider mappings](https://github.com/music-assistant/models/blob/main/music_assistant_models/media_items/provider_mapping.py), [URI construction](https://github.com/music-assistant/models/blob/main/music_assistant_models/helpers.py), [global-search failure handling](https://github.com/music-assistant/server/blob/dev/music_assistant/controllers/music/controller.py), and [official client artist/album commands](https://github.com/music-assistant/client/blob/main/music_assistant_client/music.py). Moving upstream branches are architectural evidence, not proof of a particular deployment's contract.
